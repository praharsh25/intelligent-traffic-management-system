# Intelligent Traffic Management System

**100% Software-Based IoT Simulation & Adaptive Traffic Signal Optimization**

A high-reliability, modular traffic management system designed for external practical examinations, academic viva presentations, and smart city traffic simulation research.

> ### Classroom & Examination Notice
> This project is a **100% software-based educational simulation**. It requires **no physical hardware**, microcontrollers (ESP32/Arduino), physical sensors, cameras, relays, or IoT cloud brokers. All vehicle arrivals, queue estimates, waiting metrics, and signal states are generated by an autonomous software-based stochastic simulation engine and are explicitly labeled as **SIMULATED**. This system is designed for classroom and academic demonstration only and is not certified for controlling physical road infrastructure.

## 2. Adaptive Traffic Signal Optimization Algorithm

### A. Mathematical Formulation: Transparent Priority Score
For each lane approach $d \in \{\text{North, East, South, West}\}$ at an intersection, a normalized composite priority score $P_d$ is calculated:

$$P_d = w_q \cdot \rho_d + w_w \cdot \omega_d + w_s \cdot \sigma_d + \epsilon_d$$

Where:
1. **Normalized Queue Density ($\rho_d$)** [Unitless ratio: $0.0 \le \rho_d \le 1.0$]:
   $$\rho_d = \min\left(1.0, \frac{Q_d}{Q_{\max}}\right)$$
   where $Q_d$ is the current queued vehicle count on lane $d$, and $Q_{\max} = 60$ vehicles is the simulated approach capacity.
2. **Normalized Waiting Time ($\omega_d$)** [Unitless ratio: $0.0 \le \omega_d \le 1.0$]:
   $$\omega_d = \min\left(1.0, \frac{W_d}{W_{\max}}\right)$$
   where $W_d$ is the accumulated waiting time (in seconds) of queued vehicles, and $W_{\max} = 90\text{ seconds}$ is the target maximum delay ceiling.
3. **Starvation Escalation Penalty ($\sigma_d$)** [Unitless ratio: $0.0 \le \sigma_d \le 2.0$]:
   $$\sigma_d = \begin{cases} 0.0 & \text{if } c_d < c_{\text{thresh}} \\ \min\left(2.0, \left(\frac{c_d}{c_{\text{thresh}}}\right)^{1.5}\right) & \text{if } c_d \ge c_{\text{thresh}} \end{cases}$$
   where $c_d$ is the number of consecutive signal cycles that approach $d$ has been denied green, and $c_{\text{thresh}} = 3\text{ cycles}$. This non-linear escalation prevents starvation on low-volume side streets.
4. **Tie-Breaker Perturbation ($\epsilon_d$)**:
   A deterministic/pseudo-random value $\epsilon_d \sim U(0.0, 0.015)$ to resolve equal-priority ties.
5. **Calibrated Weights**:
   $$w_q = 0.45, \quad w_w = 0.35, \quad w_s = 0.20 \quad \left(\sum w = 1.0\right)$$
6. **Emergency Priority Preemption**:
   If an emergency vehicle (ambulance/fire engine) is present on lane $d$:
   $$P_{\text{emergency}} = 999.0$$

---

### B. Dynamic Green Duration Allocation
Green time is allocated dynamically using a Webster-style proportional demand model:

$$T_{\text{green}} = \text{clamp}\left(T_{\min}, T_{\max}, T_{\min} + \text{round}\left((T_{\max} - T_{\min}) \times \frac{P_{\text{target}}}{\sum_{k} P_k}\right)\right)$$

- **Units**: Seconds ($\text{s}$).
- **Configurable Bounds**: $T_{\min} \in [3, 20]\text{ s}$ (default: $8\text{ s}$), $T_{\max} \in [8, 60]\text{ s}$ (default: $35\text{ s}$), $T_{\min} \le T_{\max}$.
- **Safety Clearance Intervals**:
  - **Yellow Interval ($T_{\text{yellow}}$)**: $3\text{ seconds}$ (NEMA TS2 amber clearance).
  - **All-Red Interval ($T_{\text{all\_red}}$)**: $1\text{ second}$ (intersection box conflict clearance).

### C. Explicit Phase State Machine & Conflict Prevention

```
┌──────────────────────────────────────────────────────────┐
│                   PHASE 1: GREEN FLOW                    │
│  - Active approach: GREEN (10s to 35s dynamic)           │
│  - Conflicting approaches: Strictly RED                  │
│  - Queue departures: 2 to 5 vehicles/second              │
└────────────────────────────┬─────────────────────────────┘
                             │ Green duration expires (phase_remaining = 0)
                             ▼
┌──────────────────────────────────────────────────────────┐
│               PHASE 2: YELLOW CLEARANCE                  │
│  - Active approach: YELLOW (3s amber clearance)          │
│  - Conflicting approaches: Strictly RED                  │
│  - Minor late departures (0 to 1 vehicle)                │
└────────────────────────────┬─────────────────────────────┘
                             │ Yellow expires (phase_remaining = 0)
                             ▼
┌──────────────────────────────────────────────────────────┐
│              PHASE 3: ALL-RED CLEARANCE                  │
│  - ALL approaches: Strictly RED (1s box clearance)       │
│  - Zero vehicle departures (prevents collisions)         │
└────────────────────────────┬─────────────────────────────┘
                             │ All-Red expires (phase_remaining = 0)
                             ▼
┌──────────────────────────────────────────────────────────┐
│                 PHASE 4: NEXT GREEN FLOW                 │
│  - Next highest priority approach receives GREEN         │
│  - Cycle increments; starvation counter resets for green │
└──────────────────────────────────────────────────────────┘
```

**Conflict Prevention Invariant Guarantee**:
At no point in time can two conflicting directions (e.g. North and East, or South and West) hold `GREEN` or `YELLOW` simultaneously. The safety assertion `optimizer.verify_conflict_free(junction)` runs on every tick.

## 3. Traffic Simulation Scenarios

The simulator provides five dynamic traffic flow profiles selectable via the dashboard or API:

| Scenario | Arrival Distribution | Rate Multiplier | Description |
| :--- | :---: | :---: | :--- |
| **Low Traffic** | Light | $0.6\times$ | Off-peak, free-flowing conditions. Short green phases. |
| **Medium Traffic** | Standard | $1.0\times$ | Normal steady-state urban city traffic flow. |
| **High Traffic** | Dense | $1.6\times$ | Heavy volume across all approaches; queues build steadily. |
| **Peak Hour (Tidal)** | Directional | $2.0\times$ | Heavy inbound North-South corridor flow with cross-traffic. |
| **Emergency Preemption** | Priority | $1.0\times$ | Emergency vehicle detected; triggers yellow clearance and immediate green corridor. |

Users can also fine-tune the **Arrival Flow Multiplier** slider from $0.5\times$ to $2.5\times$ directly on the UI.

## 7. Key Demonstration Points for Examiners

1. **Transparent Priority Score**:
   - Point out the **Score: X.XX** badge on each approach card. Explain the exact weighted formula ($0.45 \cdot \text{Queue} + 0.35 \cdot \text{Wait} + 0.20 \cdot \text{Starvation}$).
2. **Explicit 3-Phase Signal Lights**:
   - Observe the 3-dot traffic light heads change from **GREEN** $\to$ **YELLOW (3s amber clearance)** $\to$ **ALL-RED (1s box clearance)** $\to$ **GREEN**.
3. **Emergency Preemption Demonstration**:
   - Click the **🚨 Emergency Preemption** button and select an intersection approach (e.g. `J1 North`).
   - Watch the current green approach immediately enter Yellow clearance and switch safely to a priority Green corridor for the ambulance.
4. **Repeatable Viva Runs**:
   - Click **↻ Reset** and enter seed `42`. The exact same queue buildup and switching decisions will occur every time.
5. **Anti-Starvation Demonstration**:
   - Notice how lanes that have waited $\ge 3$ cycles have their priority score boosted until the optimizer awards them green, preventing side-street starvation.
6. **Traffic Burst Injection**:
   - Click **+5 Cars** on any red lane. Watch its priority score increase, compelling the adaptive controller to grant it the next green phase.
