📘 System Architecture, Methodology & Examiner Guide

Technical justification, mathematical formulations, and demonstration notes

✦

1. Adaptive Signal Optimization Formula

Each lane approach $d$ receives a normalized composite score:

P_d = 0.45·(Q_d / 60) + 0.35·(W_d / 90s) + 0.20·(c_d / 3)^1.5 + ε_d

Green time is allocated dynamically via a Webster-style proportional window:

T_g = clamp(T_min, T_max, T_min + round((T_max - T_min) * (P_d / ΣP)))

2. Safety Clearance Intervals & Conflict Prevention

Explicit 4-phase state machine prevents conflicting greens:

GREEN (10-35s) → YELLOW (3s) → ALL-RED (1s) → NEXT GREEN

Verified by safety invariant assertion on every step. Zero simultaneous conflicting green or yellow signals permitted.

3. 100% Software-Based IoT Simulation

Vehicle arrivals are generated by a stochastic Poisson-like arrival engine with configurable rate multipliers ($0.5\times$ to $2.5\times$).

Examiner Note: No physical microcontrollers, cameras, relays, or hardware are required. All readings are labeled SIMULATED.

4. Persistent SQLite Architecture

Uses WAL mode SQLite (traffic_management.db). Sessions, snapshots, lane readings, and phase changes are persisted across server restarts.

Analytics are calculated strictly via SQL aggregations, ensuring verifiable performance metrics.
